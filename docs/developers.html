How testing is organized

tests/
  conftest.py
  helpers/
  data/init_test/
  unit/           # fast, mocked
  integration/    # Selenium + examples (Chrome)

Only test_*.py files are collected. Integration covers selected examples; CRA and some demos are skipped on purpose.

Day-to-day commands

python -m pytest tests/unit -q
python -m pytest tests -q --timeout=240
ruff check glue tests
ruff format glue tests
mypy --strict glue

CI and release

What runs automatically

  • Push / PR to main → Test Glue (Ruff lint + format, mypy, pytest on Python 3.10–3.14 × Ubuntu / Windows / macOS) and CodeQL.
  • Push a version tag vX.Y.Z → Publish: build sdist/wheel, upload glue-ui to PyPI (Trusted Publishing), create a GitHub Release with artifacts.

Normal commits never publish to PyPI. Only a matching version tag does.

Cut a release

  1. Bump __version__ in glue/__init__.py and version= in setup.py to the same value (e.g. 0.6.7).
  2. Add a CHANGELOG.md section for that version.
  3. Commit and push to main (CI should go green).
  4. Tag and push the tag (must match the version string):
git tag v0.6.7
git push origin v0.6.7

If you already know you’re on latest main, you don’t need checkout / pull first.

Verify

  • GitHub → Actions → Publish is green.
  • pypi.org/project/glue-ui shows the new version.
  • Repo → Releases lists the tag.

One-time setup (PyPI Trusted Publisher + GitHub Environment pypi): see README-developers.md → Releasing to PyPI. Docs site: Settings → Pages → branch main / folder /docs.
